## 3. What wasn't done

- **The limit test isn't run in Node.** Nothing in `scripts/` opens the app's database outside the app, so the step is checked statically (its phases name real budgets) and runs on the phone.
- **The pundits' tournament still has its own draw** (P8-165). Putting it on the real one changes the verdict's replay, a decision, not a swap.
- **Profile edits**: a changed card look shows the kept one until the refresh lands, a moment after returning to You.
- D9 (the league achievements) still waits for the maintainer's marks ([`08` §5a](08-PHONE-SESSION-2.md)).

## 4. Builds

A new `preview-personal` build. Nothing native changed; the database is unchanged (version 25).

**EAS Update, from this build on.** `app.json` now has `updates.assetPatternsToBeBundled`: an update carries only the database, the globe's data, the fonts and the top-level images (about ten files), not the 780 crests and 612 flags, which every build already has. That's Expo's own switch for the 1,000-asset limit (generally available since SDK 52, [docs](https://docs.expo.dev/eas-update/asset-selection/)). Batching the upload, as one suggestion had it, isn't possible: `eas update` uploads by itself, and the limit is per update. The catch: **a new crest or flag needs a new build**, because an update won't carry it. `npx expo-updates assets:verify` checks an export against a build before publishing.
